# QUIC I/O 性能实验与测速修正（2026-09-29）

本轮运行时优化候选 C **未合入**。仅修复测试整形器逐包发送、绕过真实 UDP 批量路径的问题，
并增加回归测试和整形后的底层发送计数。应用运行代码、QUIC 依赖、H3/TLS/BBRv3 和用户配置保持 e89f1dfd6 基线，未发布版本。
修正测速工具不等于提高产品吞吐；此前发现的 STARTUP 小反向 ACK 误判仍未合入修复。

## 候选 C：只重置使用过的 UDP 发送槽位

前一轮 profile 中可见 Linux UDP 收发、TUN 写入和调度开销。本轮尝试将
`linuxBatchingConn.putSendBatch` 从每次重置全部 128 个槽位，改为只重置 `len(buffs)` 个。
QUIC 外层最多一次给出 8 个包；GSO 合并不会使用比输入包数更多的槽位，非 GSO 失败回退仍全部覆盖。
候选没有修改队列容量、等待时间、拥塞控制、MSS、认证或线上的服务。

使用独立本地/Mac worktree，基线均为 `e89f1dfd6f3c4f76c369073c7ee7cfe8202b98c1`。
Linux 候选二进制 SHA-256：`f190b4b8b4ea5f6245bbdaa66248dd044ee64efdf6dd89d7ff72279fb18f0555`。
结束后已将两个实验 worktree 的运行源码恢复到基线，补丁与二进制身份保存在证据目录。

隔离系统调用、只测向量准备和回收的 benchmark，各五次：

| 8 包批次 | 基线中位数 | 候选中位数 |
| --- | ---: | ---: |
| 不合并 GSO | 1229 ns | 92.76 ns |
| 合并 GSO | 1205 ns | 110.40 ns |

两者均为 0 alloc/op。该局部函数的节省不能换算成整条链路的提速比例。
本机无整形、每次双向各 512 MiB、各三次交错测试：吞吐中位数正向 2010.91 → 2024.11 Mbps，
反向 1987.09 → 2004.40 Mbps；全进程 CPU 秒中位数 21.84 → 21.37。
候选第三次反向仅 1828.88 Mbps，慢样本完整保留，不能据此承诺稳定加速。

同一对 jp6/jp1010 服务器，真实内核 TCP/TUN，H3/node-key/TLS 1.3/微调 BBRv3。
发送目标 1000 Mbps，每项 12 秒，单流/四流、双向，各两轮。
顺序为基线 1、候选 1、候选 2、基线 2；测试时未在这些服务器并发跑其他实验。
这里比较的是实验程序，不是下载的线上发布包。

| 方向 | 流数 | 基线两次 Mbps | 候选两次 Mbps |
| --- | ---: | --- | --- |
| jp1010 → jp6 | 1 | 239.37 / 229.16 | 244.46 / 247.17 |
| jp1010 → jp6 | 4 | 230.71 / 234.47 | 227.38 / 247.84 |
| jp6 → jp1010 | 1 | 438.00 / 429.02 | 427.81 / 441.88 |

较快方向四流有收益迹象，但 CPU 秒/GiB 未一致改善：基线 69.74 / 64.08，候选 67.88 / 69.57。
同项短窗口 TSMP p95 基线 5.51 / 7.13 ms，候选 8.98 / 12.67 ms，不能忽略延迟样本。

16 项 WAN 测量全部通过。普通 TCP 的协议层分片、发送/接收/raw/QUIC 接收队列丢弃增量均为零，
MSS 钳制生效；QUIC 判丢计数合计 392，不宣称链路零丢包。
各阶段双向 1 MiB 长度/SHA-256 探针通过；iperf 大流量本身不是整流 SHA-256 校验。
四轮均清理成功，原生产 tailscaled PID 与版本前后不变。
独立回读无本轮实验进程、服务或命名空间残留；原有 20260906 历史命名空间未改动。

## 修复测试整形器

旧 `h3BulkLink.run` 将每个到期包分别调用底层 `Bind.Send`。magicsock 对单包走
`WriteToUDPAddrPort`，因此即使上层诊断显示正在批量发送，整形后的底层也绕过了候选 C 所在路径。
前一轮及本轮旧整形器的数据属于这一模型，不能用于判定 UDP 批量优化收益，也不能将其末段速度视为 QUIC 的固有上限。
本轮旧整形器 C 对照仍保留为负对照，不用它证明 C 有效。

修正后只合并连续、同逻辑端点、同 offset、已经到期的包，受底层 BatchSize/IdealBatchSize 限制。
不提前发送、不等待凑批，不改变 FIFO、传播延迟、速率记账、借用内存拷贝或关闭清理。
不可比较的 Endpoint 使用单包回退，避免接口比较 panic。
`host_send_calls` / `host_send_packets` 记录整形后的底层发送尝试，可检查实际批次利用率；它们不是内核 syscall 计数。

同一 e89 运行代码、只切换新旧测试整形器，1 Gbps / 60 ms RTT / 512 MiB / 三轮交错：

| 方向 | 旧整形器全部 Mbps | 新整形器全部 Mbps |
| --- | --- | --- |
| 正向 | 161.74 / 168.03 / 386.90 | 386.80 / 172.44 / 390.16 |
| 反向 | 152.46 / 182.15 / 170.89 | 182.79 / 171.62 / 170.57 |

仍有明显双档波动，反向中位数几乎不变。没有把这些数字宣传为产品提速，也未证明旧整形器解释了所有慢样本。
本次合入的是已确认的测试覆盖缺陷修复，后续性能实验需从修正后的测量方法重新建立基线。

# QUIC 批量发送优化与 500 Mbps 验证（2026-09-29）

采用候选 E：可选的外层批量能力从 8 扩到最多 32，并复用发送向量，消除热路径临时数组分配。
默认 1200 字节 QUIC 包长下，真实双机快方向两轮均有吞吐、尾延迟收益；跨机 CPU 消耗总体接近原来。
**尚未证明默认配置稳定达到 500 Mbps，也没有解决慢方向及长 RTT 的吞吐问题。**
本次仅更新 dev，不创建应用或依赖版本 tag，不发布二进制；正式发布继续等待官方 1.102.6。

## 实现与边界

- 共享库新增可选 `PacketBatchSizer`。旧 writer、普通 UDP/OOB/GSO 路径仍为原先 8 槽；只有显式支持者采用 8–32 槽。
- Tailscale magicsock bridge 声明支持 32 槽，实际写出仍尊重底层 Bind 的批次上限。
- 只合并已经经过 pacing/拥塞记账、已经入队的包，不等待凑批。队列有硬上限，保留逐 UDP 包边界、错误不重试、借用内存和中继头部空间。
- 发送向量由单个 Run 循环复用；成功及失败返回都会清除引用，再归还包。单包 ACK 不再分配大数组。
- 不修改 MTU/MSS、认证、TLS、BBRv3 策略或用户配置。保留自动信任和 server 开关。

运行基线为应用 `e89f1dfd6f3c4f76c369073c7ee7cfe8202b98c1`，测量工具基线为
`34e48726c1b6d2d9b9bb26ff3df263d2bfce9462`（包含已修复的整形器）。
共享库 dev 提交 `cda3ed094749ffe253e91ab02edf4743003487d0`，应用固定 Go pseudo-version
`v0.63.0-tailscale.1.0.20260929072415-cda3ed094749`；没有本地目录 replacement。
WAN 候选二进制在隔离 worktree 用相同运行源码及本地库 replacement 编译；它不是正式发布包。
最终固定公开依赖后另做构建和 race 验证，不将实验二进制称作最终提交的发布资产。

## 默认包长：真实双机对照

同一对 jp6/jp1010，内核 TCP/TUN，发送目标 1000 Mbps，单项 20 秒，单流/四流、双向。
限定临时测试进程只使用 IPv4 外层 socket，避免上一轮 IPv4/IPv6 自动选择混杂。
测试隔离 namespace 和临时 service，未修改生产 daemon、全局路由或全局 qdisc。
H3 CONNECT-IP / node-key / TLS 1.3 / 微调 BBRv3；QUIC Initial 1200，TUN MTU 1280，MSS 1096/1076。
延迟探针覆盖负载约 17–18 秒，每项约 450–510 个 TSMP 样本；不是 iperf 应用请求延迟。
两次有效基线为 `baseline-v4-2/3`，最终候选为 `candidate-e-v4-1/2`。

## 本机与候选取舍

- D（只扩大批次）：无整形双向各 512 MiB、三轮交错，平均吞吐 2188.87 → 2418.82 Mbps，
  全进程 CPU 21.37 → 19.37 秒；但每次临时向量分配约 896 字节，WAN 分配量反而上升。
- E（D + 复用向量）：发送函数 benchmark 从 1 alloc/op、896 B/op 降为零；单包约 232 → 23 ns，
  8 包约 384 → 205 ns。这是局部函数的变化，不能等同整机提速。
- E 相对 D 的本机独立三轮无整形对照：平均吞吐 2497.52 → 2511.48 Mbps，CPU 18.58 → 18.38 秒。
- 最终 E 相对原运行基线的直接三轮无整形对照：平均吞吐 2123.47 → 2269.29 Mbps（+6.9%），
  CPU 21.09 → 18.50 秒（-12.3%）。候选第三轮反向仅 1774.67 Mbps，已包含在均值中，不能宣传每次都更快。
- E 相对原运行基线、500 Mbps/60 ms RTT/双向各 512 MiB/三轮交错：吞吐均值 173.79 → 176.33 Mbps，
  CPU 47.31 → 45.47 秒（约 -3.9%）。该模型依然没有跑满 500 Mbps。
- D 的早一组 500 Mbps 整形样本全部保留：基线平均 214.20、D 169.84 Mbps，基线包含一次 390.77 Mbps。
  已知模型存在明显双档波动，不丢掉快/慢样本，也不以该组判定固定的性能上限。
- F（E + 上一轮只清理已使用 UDP 槽位）再试一轮：快方向 448.56 / 459.99 Mbps，
  CPU 66.63 / 66.45 秒/GiB，未显示额外收益。**不合入 F 的 UDP 池清理修改。**

## MTU 诊断，不改变默认值

两台机器双向 `ping -4 -M do -s 1472 -c 3` 各 3/3 成功，证明测试时这条 ICMP 路径支持 1500 字节 IP 包。
同一候选 E 仅在实验配置将 QUIC Initial 改为 1400，保留内层 MTU 1280：
慢方向单流/四流 270.22 / 275.21 Mbps，快方向 488.74 / **530.16 Mbps**。
快方向四流 CPU 58.86 秒/GiB、P99 9.66 ms；吞吐是 20 秒接收均值，不是瞬时峰值。
随后用同样 1400 包长回测旧基线：慢方向 261.59 / 268.05 Mbps，快方向 498.17 / 515.95 Mbps。
大包下旧基线同样超过 500，因此不能把跨过 500 全部归因于新代码。仅一组大包对照，
快方向单流候选反而略慢；四流 515.95 → 530.16 Mbps，CPU 57.54 → 58.86 秒/GiB，
P99 11.69 → 9.66 ms，没有证明大包下全面提升。
这支持继续调查包数和收发开销，但没有证明所有路径可用大包。
默认仍保持 1200；magicsock bridge 没有向 quic-go 声明 DF/PMTUD 能力，
不能直接用大 Initial 代替安全的路径探测、回退与迁移处理。

## 验证、失败样本及证据

- 库 `go test -short ./...`、root/http3/ackhandler/congestion race 通过；
  新增旧 writer 回退、8–32 槽上限与非法值、背压/顺序、长短批次复用及失败后清引用测试。
- 应用固定公开依赖后 `net/batching`、`magicsock`、`quicbind`、`quicip` race 通过；
  managed lifecycle、自动信任/晚加入 peer、整形器回归 race 通过，Linux tailscaled 构建通过。
- 覆盖桥接 32 个不等长包在 host batch=7 时分成 5 次 Send；验证次序、完整字节、借用内存、33 包拒绝、错误/截止时间/关闭。
  quicbind 的 MTU 黑洞、分片/MSS、身份拒绝和重开测试包含在完整包测试中。
- 候选 E 本机 forced DERP 双向各 16 MiB 长度/SHA-256 通过，前后端点均无直连地址且 relay=test。
  它是本机中继兼容性测试，不是跨机 DERP 吞吐证明；本轮 WAN 为 IPv4，未宣称 WAN IPv6 验收。
- 首次 `baseline-v4-1` 在两项传输后发生管理端 `/metrics` 读取连接关闭，整轮失败，保留 JSON/日志。
  当时延迟采样间隔不同，不并入有效对照。之后仅对只读 `/metrics`、`/quic`、`/status` 加最多三次尝试，
  不重试有副作用的请求。各轮报告保留 cleanup 与生产进程前后回读。
- 所有成功 WAN 测量中普通 TCP 协议层分片及 raw/接收/发送/QUIC 接收队列丢弃增量均为零；
  QUIC 判丢仍非零，不能称作网络零丢包。大流量 iperf 不做整流 SHA 校验；每轮另有双向 1 MiB 长度/SHA 探针。
  本轮各本机批量文件对照均验证完整长度/SHA-256。
- 结束后独立回读：生产 PID 696 / 2251338 和版本 1.102.4 / 1.102.2 不变；
